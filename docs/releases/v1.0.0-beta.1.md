# 1.0.0-beta.1 — тестовая версия новой архитектуры

Версия доступна в ветке `testing/v1.0.0-beta.1`. Это предварительная версия для установки в отдельную папку и проверки на копии материалов. Проверка повседневной работы на чистом компьютере ещё не завершена.

## Почему 1.0.0-beta.1

Новая архитектура меняет настройку и организацию управляющего слоя: общие инструкции отделены от настроек конкретного хранилища, а первый запуск выполняется отдельной процедурой. Это первая предварительная версия будущей линии 1.0.0. Суффикс `beta.1` обозначает первый публичный тест; он не означает готовность стабильного выпуска.

## Что изменилось

### Общие инструкции и настройки разделены

В `meta/config/` появились четыре файла: карта областей работы, профиль агента, профиль трекера и требования к текстам. Начальная поставка содержит вымышленные примеры со статусом `template`; личные значения заполняются при настройке. В `meta/config/templates/` хранятся исходные шаблоны.

Скиллы читают настройки по постоянным относительным путям. Дополнительная вычитка, предзагрузка и обработка после встречи подключаются через профиль агента. Пустая точка подключения означает работу без соответствующего расширения с явной пометкой.

### Первый запуск и импорт материалов

Новый `vault-setup` задаёт до трёх вопросов об обращении и языке, областях работы и материалах для импорта. Агент заполняет обязательные настройки, создаёт папки в `01_now/ops/` и обновляет навигацию. Трекер и требования к текстам настраиваются позже, когда понадобятся.

Импорт начинается с таблицы размещения файлов. После подтверждения агент копирует внешние материалы, сохраняет источник, не перезаписывает совпавшие имена и показывает битые ссылки. Повторный запуск распознаёт уже заполненные обязательные настройки и не начинает интервью заново из-за отложенного трекера.

README содержит инструкции скачивания именно тестовой ветки через Git или ZIP с проверкой файла `VERSION`. `CLAUDE.md`, `AGENTS.md` и `START_HERE.md` используют одинаковые признаки готовности. Новые постоянные области направляются в `01_now/ops/`; `02_domains/` сохраняется как прежний раздел.

### Разбор встреч и контекст между сеансами

`meeting-processing` читает карту контуров и профиль агента вместо встроенных личных настроек. Процедура разделена на основную инструкцию и пять справочников: условия остановки, сверку с существующими записями, особые случаи, шаблон результата и проверочный список.

Перед разбором загружается объявленная текущая картина и ограниченное окно прошлых встреч. Необязательные источники, модули и трекер пропускаются с объяснением, если они не настроены или недоступны. Для обновления текущей памяти добавлена переносимая инструкция и пустая очередь спорных утверждений.

Обновлены создание проектов, парковка, восстановление работы и передача в новый диалог. В планах и очередях исполнения уточнены текущий рубеж, критерии завершения и разделение устойчивого контекста и хронологии.

### Инструкции для моделей разной мощности

Добавлено правило универсального авторинга: личные значения выносятся в настройки, действия формулируются явно, зависимости и ветки при отсутствии данных указываются рядом с шагом. Ряд скиллов переработан с учётом этих требований.

Это изменение организации инструкций, а не доказательство одинакового качества на всех моделях. Сравнительные прогоны на слабых моделях и проверка на чистом компьютере остаются задачами тестирования.

### Проверки и переносимость

Проверка публикации больше не содержит персонального стоп-листа. Она ищет общие сигнатуры ключей и личных абсолютных путей, допускает дополнительный локальный список через `--markers` и выводит только файл, строку и категорию находки. Скрытые файлы также проверяются.

Проверка ссылок отличает реальные ссылки документа от примеров внутри блоков кода. Добавлены регрессионные тесты, исправлены отсутствующие зависимости и навигация, реальные примеры заменены явно вымышленными.

## Ограничения тестовой версии

- Проверки файлов и скриптов не заменяют живую работу агента на выбранной модели.
- Настроенный трекер требует доступного в среде способа подключения; отдельный инструмент снимков трекера в комплект не входит.
- Документы управления командой разработки описывают расширенный вариант. Установщик, конфигурации ролей и полный комплект ролевых скиллов здесь не поставляются; автоматическая установка такой команды недоступна.
- Обновление существующего рабочего хранилища поверх файлов не проверено. Для теста нужна отдельная папка и копия материалов.

## Проверка на чистом компьютере

1. Передать агенту промт из раздела «Быстрый старт» корневого README.
2. Убедиться, что файл `VERSION` содержит `1.0.0-beta.1`.
3. Ответить на вопросы настройки и импортировать копию одной рабочей папки.
4. Попросить разобрать встречу, затем открыть новый сеанс и продолжить работу.
5. Записать места, где потребовались ручные команды, правка файлов, подсказки об устройстве хранилища или повторная настройка.

Команды проверок для агента:

```bash
python3 -B scripts/check_links.py .
python3 -B scripts/check_forbidden_markers.py .
python3 -B -m unittest discover -s scripts -p 'test_*.py' -v
python3 -B scripts/validate_contour_repo.py examples/github-contour-repository
```
