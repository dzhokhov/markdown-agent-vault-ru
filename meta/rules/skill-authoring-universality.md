# Авторинг скиллов и правил: универсальный текст, личное — в конфиг

## Когда применяется

При создании или правке скилла, правила, шаблона или маршрутной таблицы.

## Суть

Управляющий слой существует в одной версии: ею пользуется владелец, она же
публикуется. Текст пишется так, чтобы его выполнила и слабая модель
(инструкционная, от ~7B). Личные значения живут в `meta/config/`.

## Правила

1. **Личные значения пиши в `meta/config/` или в приватный модуль.**
   Личные значения — это карта контуров, адреса и коды проектов трекера,
   каноны письма, имена людей и компаний. В тексте скилла ставь
   относительный путь к конфигу.
   Тест: текст скилла одинаково верен в любом хранилище.
2. **Приватный модуль объявляй в `meta/config/agent-profile.md`.**
   В тексте скилла пиши оборот: «если в профиле агента задан X — выполни
   его». Имя и путь модуля живут только в профиле агента.
3. **Примеры пиши вымышленными.** Образец: контур «acme-shop», проект
   «SHOP», адрес `tracker.example.com`. Реальное имя, адрес или код
   пиши только в `meta/config/`.
4. **Ссылайся на файлы публичного дерева:** `skills/`, `meta/rules/`,
   `meta/templates/`, шаблоны `meta/config/`. Ссылку на приватный файл
   давай одним способом — через конфиг по правилу 2.
5. **Скилл из списка исключений подключай только через профиль агента.**
   В общем тексте называй роль («скилл финальной вычитки, если задан»),
   вместо имени.
6. **Пиши по нормам слабых моделей.**
   - Одно правило — одно действие.
   - Запрет ставь после позитивной нормы, в форме «вместо X делай Y».
   - У каждого шага называй точный результат: формат, путь, вид ответа.
   - Обязательный путь исполнения — не больше одного перехода по ссылке
     (текст скилла → конфиг).
   - Ядро файла — до ~150 строк; подробности выноси в справочные файлы.
   - В двусмысленном месте дай пример «плохо → хорошо», не больше трёх.
7. **У необязательной зависимости опиши ветку «если нет».** Формат ветки:
   «пропусти шаг и добавь пометку "пропущено: нет X"». Конфиг со
   `status: template` означает «настройка не проводилась»: предложи
   `vault-setup` и работай в базовом режиме.
8. **После правки запусти синхронизацию скиллов к агенту**, если она
   используется: `./skills/sync-cowork-skills.sh`.

## Чек-лист перед записью

- [ ] Личные значения — только в `meta/config/`; в тексте — пути к конфигам.
- [ ] Примеры вымышленные.
- [ ] Ссылки ведут в публичное дерево.
- [ ] Исключённые скиллы названы ролью, вместо имени.
- [ ] Одно правило — одно действие; запреты в форме «вместо X делай Y».
- [ ] Обязательный путь — не больше одного перехода; у необязательных
      зависимостей есть ветка «если нет».
- [ ] Проверка приватных маркеров по изменённым файлам пройдена: скриптом
      проверки маркеров, а без скрипта — поиском своих маркеров
      (имена, адреса, пути).
- [ ] Финальный тест: положи файл в открытый репозиторий и дай слабой
      модели. Каждая строка публикуема? Каждый шаг выполним без догадок?
