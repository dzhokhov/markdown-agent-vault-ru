# /memory-audit

## Суть

Инструкция для проверки качества долговременной памяти vault: источников, оснований, доверия, старения, конфликтов и прав на запись.

Проверка не чинит стратегические решения, цели, правила памяти, текущие картины и спорные факты автоматически. Такие изменения идут через `human_review_required`.

## Когда запускать

- По прямому запросу `/memory-audit`.
- Перед крупной пересборкой текущей картины.
- После серии встреч или импортов, если накопились новые факты, решения, гипотезы и задачи.
- Перед переносом проектных выводов в `context.md`, текущую картину или `03_knowledge`.
- При подозрении на конфликт, устаревание или превращение гипотезы в факт.

## Вход

Пользователь может указать:

- конкретный проект или контур;
- папку или набор файлов;
- текущую картину;
- профильный файл решений, фактов, гипотез, рисков или задач;
- режим `full` или `targeted`.

Если контур неоднозначен, применить Правило 6 из [AGENTS.md](../../AGENTS.md): остановиться и уточнить.

1. [Память vault](../rules/vault-memory.md).

7. Сырые источники только точечно: для проверки спорных утверждений, цитат, дат, полномочий и конфликтов.

Не читать весь архив без причины. Если контекст неполный, явно указать это в отчёте.

## Проверки

- Есть ли активные факты без источников?
- Есть ли решения без основания?
- Есть ли утверждения с `evidence.strength: low`, попавшие в текущую картину как безусловные?
- Есть ли планы после `valid_until`?
- Есть ли факты с просроченным `last_verified`?
- Есть ли конфликты без статуса?
- Есть ли карточки без `claim_type`?
- Есть ли важные изменения без записи в `meta/memory/ledger.md`?
- Есть ли утверждения, где `claim_type: inferred`, но они используются как факт?
- Есть ли карточки с `write_policy: human_review_required`, которые агент изменил сам?
- Есть ли повторяющиеся или противоречащие друг другу карточки?
- Есть ли клиентские пожелания, записанные как продуктовые обязательства без подтверждения владельца?
- Есть ли планы, гипотезы или предположения, попавшие в текущую картину как текущая реальность?
- Есть ли решения, где `authority.can_define_project_direction` отсутствует или `false`?

```md
- ...

- ...

- ...

## Conflicts

- ...

## Recommended changes

- ...

## Changes requiring human review

- ...
```

## Правила исправлений

- Низкорисковые технические исправления ссылок, дат и явных опечаток можно применять по обычному протоколу записи.
- Стратегические решения, цели, правила памяти, текущие картины и спорные факты не исправлять автоматически.
- Если нужно изменить `claim_type`, `confidence`, `last_verified`, `status`, `write_policy` или конфликт, оставить запись в [журнале изменений памяти](../memory/ledger.md).
- Если найден конфликт, создать или обновить запись по [шаблону конфликта](../templates/memory-conflict.md).
- Если слабый факт нужен для текущей картины, формулировать его как «требует проверки» или «неподтверждённое предположение».

## Следующий шаг

После аудита предложить список правок, разделённый на:

- можно применить автоматически;
- можно предложить как patch;
- требует проверки владельцем;
- лучше не трогать без первичного источника.
