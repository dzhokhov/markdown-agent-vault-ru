> **Тестовая ветка `testing/v1.0.0-beta.1` · версия 1.0.0-beta.1.** Новая архитектура с отдельными настройками и первичным запуском через `vault-setup`. Проверка на чистом компьютере ещё впереди; для теста нужна отдельная папка и копия материалов.

[Что изменилось в новой версии](./docs/releases/v1.0.0-beta.1.md) · [Скачать ZIP тестовой ветки](https://github.com/dzhokhov/markdown-agent-vault-ru/archive/refs/heads/testing/v1.0.0-beta.1.zip) · [Основная ветка](https://github.com/dzhokhov/markdown-agent-vault-ru/tree/main)

## Суть

Это русскоязычная версия стартового комплекта для человека, который хочет вести файловое хранилище вместе с AI-агентом: с правилами, структурой папок, шаблонами, скиллами, журналами и проверками.

Англоязычная версия живёт отдельно: [dzhokhov/markdown-agent-vault](https://github.com/dzhokhov/markdown-agent-vault). Это не зеркало и не дословный перевод: версии могут расходиться под разные аудитории и культурные практики работы со знаниями.

## Что решает

Обычная AI-сессия часто заканчивается тем, что:

- контекст остаётся в чате;
- файлы загружены, пересказаны и забыты;
- следующую сессию приходится вводить в курс заново;
- решения, задачи, знания и исходники расходятся по разным местам.

Этот комплект делает файловую систему устойчивым слоем состояния:

- `AGENTS.md` объясняет агенту правила работы в хранилище;
- `00_inbox/` принимает новые и неразобранные материалы;
- `01_now/` хранит активные проекты и текущую работу;
- `03_knowledge/` хранит переиспользуемые знания;
- `log.md`, `plan.md`, `tasks.md` и `context.md` помогают новой сессии продолжить работу без догадок.
- `project-creator` создаёт новый проект целиком: агент сам пишет план, очередь исполнения, контекст, журнал и входной README;
- `vault-memory` отделяет актуальную память от архива: старые встречи и логи остаются источниками, но не подменяют текущую картину;
- слой доверия к памяти заставляет важные утверждения иметь тип, источник, основание, уровень доверия и дату проверки;
- `context-compression` сжимает историю регулярных встреч, чтобы агент не перечитывал весь архив и не принимал устаревшие решения за актуальные.

Дополнительный режим — [контурный GitHub-репозиторий](./docs/github-contour-repositories.md): отдельный репозиторий для долгоживущей области работы, где агент готовит изменения через ветку и заявку на изменение, а человек получает понятное описание риска и результата.

## Кому полезно

Комплект полезен, если ты:

- работаешь с агентами, которые умеют читать и менять локальные файлы;
- ведёшь заметки в Markdown или Obsidian;
- хочешь, чтобы состояние проекта переживало отдельные чаты;
- хочешь понятный порядок для входящих материалов, задач, решений и знаний;
- предпочитаешь обычные файлы, а не закрытую «память» внутри сервиса.

Это не:

- SaaS-приложение;
- Obsidian-плагин;
- магическая память;
- замена трекера задач;
- универсальная методология для всех людей и культур.

## Режимы использования

### Личное локальное хранилище

Основной режим: один владелец ведёт рабочую папку с агентом. Состояние проекта живёт в файлах, а агент соблюдает `AGENTS.md`, правила маршрутизации, индексы и журналы.

### Контурный GitHub-репозиторий

Режим для команды, продукта, клиента или другой долгоживущей области. Один контур живёт в одном репозитории; границы описывает `repository-manifest.yml`; изменения идут через заявку на изменение; закрытые данные не смешиваются с обычным слоем.

См. руководство [Контурные GitHub-репозитории](./docs/github-contour-repositories.md) и пример [examples/github-contour-repository](./examples/github-contour-repository/README.md).

## Быстрый старт

Нужен агент, который умеет читать и менять файлы в выбранной папке. Для автоматического скачивания ему также нужны доступ к сети и запуск команд. Передай ему этот промт:

```text
Разверни тестовую версию 1.0.0-beta.1 файлового хранилища:
https://github.com/dzhokhov/markdown-agent-vault-ru/tree/testing/v1.0.0-beta.1

Все команды выполняешь ты; я отвечаю в чате и не редактирую файлы руками.
1. Спроси, в какой НОВОЙ папке разместить хранилище, и дождись ответа.
   Существующие файлы не перезаписывай. Корректно заключай пути с пробелами
   в кавычки во всех командах.
2. Если git доступен, клонируй только тестовую ветку в выбранную папку:
   git clone --branch testing/v1.0.0-beta.1 --single-branch https://github.com/dzhokhov/markdown-agent-vault-ru.git <новая-папка>
3. Если git недоступен, скачай ZIP и распакуй его средствами своей среды:
   https://github.com/dzhokhov/markdown-agent-vault-ru/archive/refs/heads/testing/v1.0.0-beta.1.zip
   Проверь успешность скачивания и распаковки. При ошибке остановись
   и объясни её; другую ветку вместо этой не скачивай.
4. Проверь VERSION в корне: ожидается 1.0.0-beta.1. Другое значение — стоп.
5. Прочитай START_HERE.md и AGENTS.md, затем skills/vault-setup/SKILL.md.
6. Проведи первичную настройку. Обязательны contours-map.md и agent-profile.md
   со status: active; tracker-profile.md и writing-canons.md разрешено оставить
   шаблонными. Не предлагай повторную настройку из-за этих двух файлов.
7. Если я передам материалы для импорта, сначала покажи план размещения.
   После подтверждения копируй их, сохраняя исходную папку.
```

Запасной путь: [скачать ZIP тестовой ветки](https://github.com/dzhokhov/markdown-agent-vault-ru/archive/refs/heads/testing/v1.0.0-beta.1.zip), распаковать его и показать агенту папку со словами: «Прочитай START_HERE.md и настрой это хранилище».

## Первый тест

После настройки передай копию одной рабочей папки, попроси разобрать встречу и продолжи работу в новом сеансе. Отмечай повторную настройку, неверное размещение файлов и места, где пришлось вручную объяснять агенту устройство хранилища. Подробный сценарий и ограничения — в [описании тестовой версии](./docs/releases/v1.0.0-beta.1.md).

## С какими агентами можно использовать

Подойдёт любой агент, который умеет работать с локальной папкой: читать Markdown-файлы, создавать новые файлы, менять существующие и запускать простые проверки.

| Агент | Когда выбрать |
|---|---|
| [OpenAI Codex](https://github.com/openai/codex) | Если нужен агент в терминале, редакторе или отдельном приложении; хорошо подходит для работы с локальной папкой и правилами `AGENTS.md`. |
| [Claude Code](https://docs.anthropic.com/en/docs/claude-code/overview) | Если удобен агент в терминале или редакторе, который читает проект, меняет файлы и выполняет команды. |
| Claude Cowork | Если работаешь в Claude Desktop и хочешь дать агенту доступ к папке хранилища. Ограничение: Cowork не читает скиллы из `skills/` напрямую как живую папку. Обходной путь — скрипт [skills/sync-cowork-skills.sh](./skills/sync-cowork-skills.sh), который синхронизирует скиллы из папки `skills/` в места, откуда их видит Cowork. |
| [Cursor](https://cursor.com/) | Если хочешь работать внутри редактора, похожего на VS Code, с AI-помощником по всей папке. |
| [Windsurf](https://windsurf.com/) | Ещё один редактор с агентским режимом и пониманием проекта. |
| [Cline](https://cline.bot/) | Расширение для редактора: можно подключать разные модели и держать действия агента под явным контролем. |
| [Gemini CLI](https://github.com/google-gemini/gemini-cli) | Терминальный агент от Google; полезен, если нужен открытый инструмент с доступом к файлам и командам. |
| [Google Antigravity](https://antigravity.google/) | Подходит, если нужен режим управления агентами: можно запускать и отслеживать несколько агентов по разным рабочим папкам. |
| [GitHub Copilot coding agent](https://docs.github.com/copilot/concepts/coding-agent/about-copilot-coding-agent) | Подходит, если хранилище лежит на GitHub и хочется поручать изменения через задачи и pull request. |

Методология не привязана к одному поставщику. Главное требование: агент должен сначала читать `AGENTS.md`, а затем соблюдать правила маршрутизации файлов, журналов, задач и знаний.

### Важно про Claude Cowork

Claude Cowork может работать с этим хранилищем, но у него есть ограничение: скиллы из папки `skills/` не подхватываются автоматически как единый живой источник.

Для синхронизации в комплект входит скрипт:

```bash
./skills/sync-cowork-skills.sh
```

После правки скилла нужно снова запустить синхронизацию или проверить состояние:

```bash
./skills/sync-cowork-skills.sh --status
./skills/sync-cowork-skills.sh
```

По умолчанию скрипт синхронизирует все скиллы, у которых есть `SKILL.md`. Список можно ограничить через переменную окружения:

```bash
COWORK_SKILLS="research parking resume" ./skills/sync-cowork-skills.sh
```

## Чем отличается

| Альтернатива | Что даёт | Чем отличается этот комплект |
|---|---|---|
| Один `AGENTS.md` | Правила поведения агента | Здесь есть вся файловая архитектура: входящие, проекты, знания, журналы, шаблоны, скиллы и маршрутизация |
| Basic Memory и похожие инструменты | Слой памяти и поиска по заметкам | Здесь фокус на файловом состоянии проектов, решениях, задачах и исходниках |
| Cline Memory Bank | Проектные файлы памяти для разработки | Здесь подход шире: не только код, но и исследования, встречи, знания, входящие материалы и журналы |
| Obsidian-плагины | Интерфейсные функции и автоматизация внутри Obsidian | Это не плагин, а файловая конвенция и рабочий порядок для агента |
| Обычное Obsidian-хранилище | Заметки и ссылки для человека | Здесь добавлены правила для агента, проектные state-файлы, жизненный цикл и проверки |

## Зрелость

Статус: ранний русскоязычный стартовый комплект.

Готово:

- переносимая структура папок;
- правила агента;
- шаблоны проектов;
- автономное создание проектов через `project-creator`;
- маршрутизация материалов;
- правило актуальной памяти и слой доверия к утверждениям;
- сжатие истории регулярных встреч;
- онбординг;
- скиллы;
- локальные проверки;
- минимальный пример первого цикла;
- минимальный режим контурного GitHub-репозитория с манифестом, шаблонами, примером и проверкой.

Пока не готово:

- широкие инструкции под все агентские инструменты;
- внешние пользовательские примеры;
- стабильная совместимость с любым агентом;
- зрелая публичная модель вкладов.

## Проверка

Из корня репозитория:

```bash
python3 scripts/inventory.py
python3 scripts/check_links.py
python3 scripts/check_forbidden_markers.py
```

Для проверки примера контурного GitHub-репозитория:

```bash
python3 scripts/validate_contour_repo.py examples/github-contour-repository
```
