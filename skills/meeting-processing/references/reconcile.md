# Шаг 5. RECONCILE — сверка знаний с хранилищем (подробно)

Встреча приносит факты, метрики и решения, которые могут устарить или дополнить уже записанное. Плюс встречи несут контекст: процессы сломались, метрики изменились, появились ограничения и зависимости. Без проактивного извлечения этот контекст остаётся погребён в файле саммари. Шаг решает обе задачи. Все примеры ниже вымышленные (контур `acme-shop`, компания «Acme», люди «Анна П.», «Виктор С.»).

## 5.1. Фильтр долгоживущих знаний (KNOWLEDGE FILTER)

**Вход**: результат Шага 1 (EXTRACT) + текущий `context.md` головной папки контура (прочитай на этом шаге, если не прочитан раньше).

**Цель**: отделить факты, которые обновляют постоянные знания контура, от эфемерики. 90% информации на встречах эфемерно; без фильтра `context.md` раздуется и потеряет инвариантность.

Для каждого извлечённого элемента (решение, метрика, факт, развилка, корневая причина) примени четыре эвристики:

| Эвристика | Вопрос | Пример прохождения | Пример провала |
|-----------|--------|---------------------|----------------|
| **Будущая сессия** | Если следующий агент, работающий с контуром, не будет знать этот факт — пострадает ли качество его решений? | «Закрытие месяца теперь занимает 10 рабочих дней вместо 5» — да, влияет на планирование | «Анна П. пришла на встречу с опозданием» — нет |
| **Уникальность** | Факт уже есть в `context.md` или базе знаний? Если есть — изменилось ли значение? | Новая метрика, отсутствующая в context.md — уникально | Повторение уже записанного термина — не уникально |
| **Устойчивость** | Факт останется верным через 3 месяца? | «Возвраты достигают 12% заказов» — да (системная проблема) | «Виктор С. болел на этой неделе» — нет |
| **Источник** | Прозвучало как утверждение/решение от ответственного лица или как гипотеза/мнение? | Руководитель направления назвал цифру — надёжно | «Мне кажется, может быть...» — гипотеза, не факт |

Элемент прошёл **хотя бы 3 из 4** эвристик → кандидат на запись в постоянные знания (ADD / UPDATE / LINK / EXTRACT-TO-KB, п. 5.3).

Элемент не прошёл фильтр → **NOOP**: остаётся в `## Упомянуто вскользь` с canonical-тегом из [meta/TAGS.md](../../../meta/TAGS.md#task-routing-tags). Пассивный механизм «3+ упоминания в разных встречах → предложить формулировку для context.md» продолжает работать как дополнительный триггер, но не заменяет проактивную фильтрацию.

**Пять категорий долгоживущих знаний со встреч** (что искать):

1. **Изменения состояния контура**: метрики, процессы, инструменты, роли изменились.
2. **Обоснование решений**: почему выбрали A, а не B (самое ценное — без обоснования решение через 3 месяца превращается в «так исторически сложилось»).
3. **Новые инварианты**: термины, ограничения, зависимости, которых раньше не знали.
4. **Новые связи между сущностями**: человек↔область, проект↔инструмент, контур↔ограничение.
5. **Корректировка существующих знаний**: «раньше думали X, теперь знаем Y».

Методологическая база (по именам): пирамида DIKW — переход Information→Knowledge; модель LangMem — семантическая память и консолидация; pipeline Mem0 — операции ADD/UPDATE/DELETE/NOOP.

## 5.2. Где искать пересечения

Ищи внутри контура и связанных доменов:

| Где искать | Что проверять |
|------------|---------------|
| `context.md` головной папки контура | Стратегические утверждения, цели, текущий статус, инварианты |
| `status.md` / `overview.md` (если есть) | Операционные метрики, состояние команд, текущие проблемы |
| `tasks.md` всех затронутых проектов | Задачи, которые встреча закрыла, изменила или сделала неактуальными |
| `materials/` — стратегии, планы | Документы, чьи предпосылки или выводы изменились |
| База знаний хранилища — глоссарии, таксономии | Новые термины, изменения в классификациях |
| Реестр людей и карточки (правило people-linking) | Новые роли, смена ответственности, увольнения |
| Другие проекты контура | Метрика или факт из встречи пересекается с другим проектом |

## 5.3. Алгоритм

1. **Собери факты из встречи** — всё из слоя «Метрики/факты» + ключевые утверждения из «Решений» и «Стратегических развилок». Каждый факт — отдельная единица сверки.
2. **Примени KNOWLEDGE FILTER (п. 5.1)** к каждому факту. Раздели на кандидатов (прошли ≥3 эвристики) и эпизодику.
3. **Для каждого кандидата — поиск по хранилищу**: найди файлы контура с той же темой/метрикой/сущностью; сравни — значение совпадает, устарело или отсутствует.
4. **Классифицируй расхождения**:

   | Тип | Что происходит | Действие |
   |-----|---------------|----------|
   | **UPDATE** | Факт в хранилище устарел — встреча дала свежие данные | Предложи замену с указанием старого и нового значения |
   | **ADD** | Факт новый, есть подходящий файл | Предложи добавить в конкретную секцию конкретного файла |
   | **FLAG** | Факт противоречит записанному, непонятно что правильнее | Покажи противоречие, спроси владельца |
   | **EXTRACT-TO-KB** | Знание шире одного контура (методология, рыночный факт, паттерн) | Предложи файл в базе знаний (новый или обновление) |
   | **NEW_FILE** | Факт важный, места в существующих файлах нет | Предложи создать файл (только при реальной необходимости — анти-фрагментация) |
   | **LINK** | Новая связь между известными сущностями | Обнови соответствующий индекс (context.md, README, реестр) |
   | **TASK_CLOSE** | Встреча закрыла задачу из tasks.md | Предложи отметить `[x]` с датой и ссылкой на встречу |
   | **NOOP** | Информация не прошла фильтр — эфемерна | Остаётся в `## Упомянуто вскользь` с canonical-тегом |

5. **Сформируй RECONCILE-отчёт** и покажи пользователю в чате. Формат (пример вымышленный):

```
## Сверка знаний со встречи с хранилищем

### Обновление постоянных знаний (прошли KNOWLEDGE FILTER ≥3/4 эвристик)

#### UPDATE (обновить существующие данные)
1. **Файл**: context.md головной папки контура acme-shop
   **Секция**: «Финансовая отчётность»
   **Было**: «Закрытие месяца — 5 рабочих дней»
   **Стало**: «Закрытие месяца — 10 рабочих дней (после разделения по юрлицам)»
   **Источник**: встреча 2026-04-15, слова Анны П. (руководитель финансов)
   **Эвристики**: будущая сессия ✓, уникальность ✓ (значение изменилось), устойчивость ✓, источник ✓

#### ADD (добавить новые данные)
1. **Файл**: context.md головной папки контура acme-shop
   **Секция**: «Известные проблемы» (новая)
   **Добавить**: «Возвраты достигают 12% заказов. Причина: ручная проверка адресов, ежеквартальная сверка.»
   **Источник**: встреча 2026-04-15
   **Эвристики**: будущая сессия ✓, уникальность ✓, устойчивость ✓ (системная проблема), источник ✓

#### EXTRACT-TO-KB (знание шире контура)
1. **Предлагаемый файл** (в базе знаний): сравнение BI-инструментов для финансовых дашбордов
   **Обоснование**: полезно за пределами контура acme-shop

#### FLAG (требует решения)
1. **Противоречие**: в context.md указано X, на встрече сказано Y. **Вопрос**: что актуально?

#### TASK_CLOSE (задачи для закрытия)
1. **Файл**: 2026-acme-shop-funnel/tasks.md
   **Задача**: `- [ ] проверить воронку пресейла`
   **Закрыть**: обсудили на встрече, решение принято.

### Не проходят KNOWLEDGE FILTER → «Упомянуто вскользь»
- Анна П. тестирует LLM в таблицах → #automation
- сервис аналитики не удаляет данные автоматически → #ops-risk
```

6. **Дождись подтверждения пользователя.** Пользователь может:
   - «ок» → применить все предложения;
   - «ок, кроме #3» → применить частично;
   - «не надо» → пропустить RECONCILE, перейти к WRITE;
   - поправить конкретные пункты;
   - перевести элемент из «Не проходят фильтр» в ADD/UPDATE (считает факт важнее, чем решил агент);
   - перевести элемент из ADD/UPDATE в NOOP (считает факт эфемерным).
7. **Примени подтверждённые изменения** — каждое с MR-паттерном (diff перед записью). Подтверждено пакетно → записать всё за один проход. NOOP-элементы идут в `## Упомянуто вскользь` файла саммари.

## Ограничения RECONCILE

- Файлы вне контура правь только по явному указанию пользователя.
- Данные не удаляй — только обновляй и добавляй. Кажется устаревшим, но неясно → FLAG, вместо UPDATE.
- Новый файл ради одного факта не создавай (анти-фрагментация). Новый файл — только при критической массе новых знаний.
- Расхождений больше 10 → сгруппируй по файлам и покажи сводку, вместо стены текста.
