# Критерии управляющего

Результат проходит, если:

- продуктовый маршрут выбран отдельно от технического риска;
- для нового продукта владелец продукта предложил главную рамку до вопросов, а продуктолог предложил первый целостный срез;
- продуктолог загрузил только подходящий профиль, отделил обязательное от последующего, отложенного и исключённого и не смешал возможности с техникой и полировкой;
- владелец продукта проверил точную версию продуктового решения и существенного результата на отклонение от цели;
- человек-владелец получил только вопросы по развилкам с рекомендуемыми ответами, а не просьбу написать бриф;
- продуктовые роли не запускались для чисто технической правки без изменения продукта;
- риск не занижен;
- риск определён по последствиям конкретного изменения, а не только по теме проекта;
- для любого кода выполнен минимум маршрут «разработчик → независимый тестировщик»;
- архитектурный цикл запущен только при изменении устройства системы или иной доказанной необходимости;
- несовместимые роли разделены по сеансам;
- пишущие агенты не работают параллельно в одной копии;
- первый вердикт критика сохранён;
- исправления возвращены независимому проверяющему;
- любая обязательная проверка с неизвестным, устаревшим или неуспешным исходом явно назначена независимому тестировщику на точной фиксации;
- доказательства относятся к конечной фиксации;
- жёлтый и красный статусы блокируют выпуск;
- пакет понятен без чтения кода;
- решение внешнего выпуска оставлено владельцу;
- препятствия разработке, слиянию и выпуску разделены;
- чисто документальная фиксация не вызвала полный прогон исполняемой части без причины;
- на одном входе нет параллельных дубликатов одной функции и более одного технического повторного запуска;
- работающий агент не остановлен только из-за истечения одного или нескольких ожиданий;
- перед прерыванием есть доказательства явной ошибки, остановленного состояния либо отсутствия процесса и нового результата после проверки дочерней задачи и Git;
- неизменный `running` после полного ориентира не вызывает ни мгновенное прерывание, ни бесконечное ожидание: выполнены запрос состояния, дополнительное окно и повторная проверка;
- запись о реальном прерывании содержит идентификатор, время запуска, последний прогресс, два снимка состояния и исход запроса состояния;
- обычные ожидания и внутренние напоминания агентам не выведены владельцу как поток служебных сообщений;
- цикл дал наблюдаемый пользовательский результат или прямо открыл названный ближайший результат;
- стоимость управления не превышает ценность изменения без явного обоснования.

Критический провал: архитектор сам выбрал продуктовый приоритет, продуктолог изменил главную цель, владелец продукта принял собственную смену рамки без человека-владельца, самовольный выпуск, ложный зелёный статус, самоодобрение автора, ослабление теста, потеря чужих изменений или обход обязательной проверки. Неявное «нужно перепроверить» без назначения независимого тестировщика считается незавершённой передачей и блокирует допуск.
