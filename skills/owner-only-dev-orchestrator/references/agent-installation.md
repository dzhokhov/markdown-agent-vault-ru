# Установка скиллов и пользовательских агентов

> **Граница тестовой поставки.** Ниже описан полный вариант команды. В этой версии нет установщика, конфигураций агентов из `assets/` и полного комплекта ролевых скиллов. Автоматическая установка команды из этой папки недоступна. Сначала проверь наличие каждого упомянутого файла; отсутствующие команды не запускай и успешную установку не заявляй. Первичная настройка хранилища через `vault-setup` от этой команды не зависит.

## Пользовательские скиллы

Канонические каталоги одиннадцати скиллов находятся в `skills/` хранилища. Codex обнаруживает личные скиллы в `~/.codex/skills/`, поэтому для текущего компьютера там должны находиться символические ссылки на:

- `owner-only-dev-orchestrator`;
- `product-owner`;
- `productologist`;
- `solution-architect`;
- `architecture-critic`;
- `architecture-fixer`;
- `implementation-developer`;
- `test-gates`;
- `test-fixer`;
- `technical-documenter`;
- `release-rollback`.

Ссылка предпочтительнее копии: канонический текст остаётся один, а установленная версия не расходится с хранилищем. Проверь каждую ссылку через `readlink`, существование целевого `SKILL.md` и распознавание `$owner-only-dev-orchestrator` в новом безопасном сеансе Codex без прямого пути в запросе.

## Канонические файлы

Девять конфигураций хранятся в `assets/agents/` этого скилла. Codex загружает личные конфигурации из `~/.codex/agents/`.

Технические имена должны совпадать:

- `product_owner`;
- `productologist`;
- `dev_architect`;
- `architecture_critic`;
- `architecture_fixer`;
- `implementation_developer`;
- `independent_tester`;
- `test_fixer`;
- `technical_documenter`.

## Проверка установки

1. Проверь одиннадцать ссылок в `~/.codex/skills/` и существование одиннадцати целевых `SKILL.md`.
2. Убедись, что в `~/.codex/agents/` есть девять одноимённых файлов.
3. Сравни каждую установленную конфигурацию агента с канонической побайтово.
4. Разбери TOML и проверь существование пути `skills.config.path`.
5. Убедись, что `architecture_critic` имеет `sandbox_mode = "read-only"`.
6. Убедись, что `independent_tester` имеет `sandbox_mode = "workspace-write"`, но его инструкции запрещают менять отслеживаемые файлы и требуют проверять состояние Git.
7. В новом сеансе распознай внешнюю команду, затем запусти безопасное задание каждой роли и проверь, что роль использует свой скилл.

## Перенос хранилища

Пути к `SKILL.md` абсолютны для текущего компьютера. После переноса пересоздай одиннадцать символических ссылок, замени корневую часть пути в канонических и установленных конфигурациях агентов, снова проверь пары и только затем запускай команду. Не считай старую установленную копию или ссылку источником правды.
