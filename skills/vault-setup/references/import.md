# Шаг 4. Импорт существующих материалов (подробно)

Когда выполняется: владелец назвал путь к папке с материалами в вопросе 3
стартового интервью — или попросил перенести папку позже. Все примеры ниже
вымышленные: папка `~/Documents/work-notes`, контур `acme-shop`.

## 4.1. Проверь папку

1. Проверь, что папка по названному пути существует и читается.
2. Папки нет — переспроси путь один раз: «Папка не найдена по пути <путь>.
   Проверь путь и пришли ещё раз — или скажи „без импорта“».
3. Второй путь тоже не найден — продолжи настройку без импорта и добавь
   в отчёт шага 5 пометку «пропущено: папка для импорта не найдена».

## 4.2. Осмотри содержимое

1. Перечисли верхний уровень папки: подпапки и файлы.
2. Посчитай файлы по типам (md, docx, pdf, прочее) — числа пойдут
   в план размещения и в отчёт.
3. Вглубь файлы не читай: для плана достаточно имён и структуры.
   Открой файл, только если по имени нельзя понять тему.

## 4.3. Составь план размещения — ДО переноса

1. Сопоставь каждую подпапку и заметные отдельные файлы с контурами
   из интервью.
2. Правила назначения:
   - материал по смыслу относится к контуру → `01_now/ops/<контур>/`;
   - тема самостоятельная и не подходит ни одному контуру →
     предложи новый контур отдельной строкой плана;
   - тема неясна → `00_inbox/`.
3. Выведи план таблицей и жди ответа владельца:

| Что | Куда | Почему |
|---|---|---|
| `work-notes/shop/` (12 файлов) | `01_now/ops/acme-shop/materials/` | заметки магазина |
| `work-notes/старая-переписка.docx` | `00_inbox/` | тема неясна |

4. Владелец сказал «ок» — переходи к переносу. Владелец поправил —
   обнови таблицу и покажи снова. Больше двух кругов правок не делай:
   спорные позиции отправь в `00_inbox/` и пометь это в плане.

## 4.4. Перенеси файлы

1. Папка-источник лежит вне хранилища — копируй файлы в хранилище;
   исходную папку не меняй и не удаляй.
2. Папка-источник лежит внутри `00_inbox/` хранилища — перемести файлы
   на целевые места.
3. Структуру подпапок внутри целевой папки сохраняй как в источнике.
4. Ничего не перезаписывай: имя на целевом месте занято — добавь
   к имени переносимого файла суффикс `-imported`.

## 4.5. Создай недостающие служебные файлы

1. В каждой головной папке контура, куда легли материалы, должен быть
   `README.md`: frontmatter — по разделу 1
   [протокола записи](../../../meta/rules/write-protocol.md); тело —
   `## Суть` (что за контур), `## Детали` (что лежит, откуда
   импортировано), `## Следующий шаг`.
2. Там же создай `context.md`, если владелец назвал устойчивые сведения
   о контуре: чем область живёт, какие в ней главные термины. Пары
   предложений достаточно.
3. Новые контуры из плана размещения зарегистрируй строками
   в `meta/config/contours-map.md` — по правилам шага 2 ядра скилла.

## 4.6. Отчёт о битых ссылках

1. Пройди перенесённые `.md`-файлы и собери из них markdown-ссылки
   с относительными путями.
2. Проверь каждую ссылку от нового места файла: цель существует?
3. Битые ссылки выведи списком: «файл → ссылка → почему не работает».
4. Ссылки на старое место (в исходную папку или прежнее хранилище)
   ожидаемы: покажи их в том же списке, не чини молча. Чини только те,
   которые владелец попросил починить.

## 4.7. Заверши импорт

1. Материалы брались из `00_inbox/` — добавь запись
   в `00_inbox/PROCESSING_LOG.md`: что обработано, куда перенесено.
2. Передай в отчёт шага 5 числа: сколько файлов перенесено, в какие
   папки, сколько битых ссылок в списке.
