# vault-setup — первичная настройка хранилища

## Назначение

Скилл превращает хранилище с шаблонными конфигами в настроенное.
Владелец отвечает на вопросы в чате. Агент сам пишет файлы.
Терминал и git не нужны: каждый шаг — чтение или запись файла.

## Точки входа

| Откуда пришли | Что делать |
|---|---|
| Bootstrap-промт из README репозитория: хранилище только что скачано | Начни с шага 0 |
| Отсутствует или шаблонный обязательный конфиг contours-map/agent-profile | Начни с шага 0 |
| Шаблонный только tracker-profile или writing-canons | Первичную настройку не повторяй; настрой нужный конфиг отдельно по запросу |
| Прямая просьба владельца: «настрой хранилище», «первый запуск» | Начни с шага 0 |
| Просьба про импорт при уже настроенном хранилище | Выполни только шаг 4 |

## Шаг 0. Проверь состояние конфигов

1. Прочитай frontmatter четырёх файлов в `meta/config/`: `contours-map.md`,
   `tracker-profile.md`, `writing-canons.md`, `agent-profile.md`.
2. Состояние конфига: `status: template` — настройка не проводилась;
   `status: active` — конфиг заполнен.
3. Файла нет — скопируй одноимённый шаблон из `meta/config/templates/`
   в `meta/config/`. Шаблона тоже нет — продолжай без этого конфига
   и добавь в отчёт шага 5 пометку «пропущено: нет конфига <имя>».
4. `contours-map.md` и `agent-profile.md` уже `active` — сообщи владельцу:
   «хранилище настроено». Если пользователь уже назвал действие, продолжай его; иначе уточни нужную точечную правку без повторного интервью. Шаблонные tracker-profile и writing-canons этому не мешают.
5. Иначе — переходи к шагу 1.

## Шаг 1. Стартовое интервью — не больше трёх вопросов

Задай три вопроса одним сообщением. Дождись ответов. Других вопросов не задавай.

1. **Как к тебе обращаться и на каком языке работать?**
   Пример ответа: «Аня, на „ты“, русский».
2. **Какие области работы (контуры) завести?** Название и пара слов о каждой.
   Пример ответа: «acme-shop — мой интернет-магазин; personal-blog — личный блог».
3. **Есть ли папка с материалами, которые перенести в хранилище?**
   Пример ответа: «~/Documents/work-notes» — или «нет».

Ответ «не знаю» — возьми значение по умолчанию и пометь в отчёте шага 5
словами «по умолчанию». Значения по умолчанию: (1) язык сообщений владельца,
обращение на «ты»; (2) один контур `main` — «основная работа»; (3) без импорта.

Трекер, вики, каноны письма, модули и подключение скиллов к агенту на входе
не настраиваются. Это отложенная настройка: её предложит тот скилл, которому
она первому понадобится.

## Шаг 2. Заполни конфиги по ответам

Заполняй только шаблонные конфиги. Конфиг со `status: active` не перезаписывай.

1. `meta/config/contours-map.md`: по строке таблицы на каждый контур из
   ответа 2. Головная папка — `01_now/ops/<имя-контура>/`; колонка
   «Встречи» — `meetings/` с пометкой «создать при первой встрече»;
   остальные колонки — прочерк. Строки вымышленного примера удали.
2. `meta/config/agent-profile.md`: в разделе «Личные предпочтения поверх
   универсальных правил» запиши строку с обращением и языком из ответа 1.
   Разделы «Финальная вычитка» и «Модули meeting-processing» не заполняй.
3. `meta/config/tracker-profile.md` и `meta/config/writing-canons.md`
   не заполняй: они остаются шаблонами до первой надобности — первой
   задачи во внешнем трекере, первого локального канона письма.

## Шаг 3. Сними статус «шаблон» и создай папки контуров

1. В `contours-map.md` и `agent-profile.md` замени `status: template`
   на `status: active` и поставь сегодняшнюю дату в поле `updated`.
2. Удали из этих двух конфигов блок-предупреждение «Это шаблон…»
   под заголовком.
3. Обнови индексы `01_now/README.md` и `01_now/ops/README.md` ссылками на созданные области.
4. Для каждого контура создай папку `01_now/ops/<имя-контура>/` с файлом
   `README.md`. Frontmatter — по разделу 1
   [протокола записи](../../meta/rules/write-protocol.md). Тело: `## Суть` —
   одно предложение о контуре из ответа 2; `## Детали` — что будет лежать
   в папке; `## Следующий шаг`. Шаблон `meta/templates/project_README.md`
   не используй: он для проектов со служебными файлами plan и tasks,
   а не для головной папки контура.

## Шаг 4. Импорт существующих материалов

Выполняй, только если в ответе 3 назван путь. Полная процедура —
[references/import.md](./references/import.md). Контракт шага:

1. Покажи план размещения таблицей «что → куда → почему» ДО переноса.
2. Дождись «ок» владельца — и только потом переноси.
3. Материалы контура — в `01_now/ops/<контур>/`; неразобранное — в `00_inbox/`.
4. Создай недостающие `README.md` и `context.md`; новые контуры
   зарегистрируй строками в `meta/config/contours-map.md`.
5. Битые ссылки покажи списком. Ссылки на старое место ожидаемы —
   не чини молча.
6. Ничего не удаляй: файлы из папки вне хранилища копируй,
   источник не трогай.

Папка по названному пути не существует — переспроси путь один раз.
Второй путь тоже не найден — продолжи без импорта и добавь в отчёт
пометку «пропущено: папка для импорта не найдена».

## Шаг 5. Финал — отчёт и запись в журнал

1. Выведи владельцу строку-отчёт. Формат: «Настроено: контуры <список>;
   обращение и язык; импорт <N файлов>. Отложено: трекер, вики, каноны
   письма, модули — настроим при первой надобности».
2. Создай файл `04_logs/<ГГГГ-ММ-ДД>-vault-setup.md`: frontmatter —
   по разделу 1 [протокола записи](../../meta/rules/write-protocol.md);
   тело — тот же отчёт плюс список созданных и изменённых файлов.

## Ветки «если нет» — сводка

| Чего нет | Что делать |
|---|---|
| Терминала или git | Работай как обычно: скиллу хватает чтения и записи файлов |
| Файла конфига | Скопируй шаблон из `meta/config/templates/`; нет и шаблона — пометка «пропущено» в отчёте |
| Папки для импорта | Переспроси путь один раз, дальше продолжай без импорта с пометкой |
| Ответа на вопрос («не знаю») | Значение по умолчанию из шага 1 и пометка «по умолчанию» |
